# 정리 후보 탐지와 안전한 정리

## 탐지 규칙

| 유형 | 폴더 | 파일 |
|---|---|---|
| Node.js | `node_modules` | – |
| 빌드 결과물 | `dist`, `build`, `out`, `cmake-build-*`, `target`\*, `bin`\*, `obj`\* | – |
| 개발 캐시 | `.cache`, `.next`, `.nuxt`, `.vite`, `.parcel-cache`, `.turbo`, `.svelte-kit`, `.angular`, `__pycache__`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `.tox`, `.nox`, `.hypothesis`, `.gradle`\*, `.vs`\* | – |
| 임시 파일 | `.tmp`, `.temp` | `*.tmp` |
| 로그 | – | `*.log` |

\* 같은 폴더에 해당 프로젝트 표시 파일이 있을 때만 후보입니다(`target`: `Cargo.toml`·`pom.xml`, `bin`·`obj`·`.vs`: `*.csproj`·`*.fsproj`·`*.vbproj`·`*.sln`,
`.gradle`: Gradle·Maven 파일). 그래서 사용자 폴더의 `bin`이나 홈의 `.gradle`(설정·인증 정보 포함)은 후보가 되지 않습니다.

개발 환경은 폴더 이름(예: `__pycache__` → Python)이나 같은 폴더의 표시 파일(`package.json`, `pyproject.toml`·`requirements.txt`,
`Cargo.toml`, `pom.xml`·`build.gradle`, `*.csproj`·`*.sln`, `CMakeLists.txt`·`Makefile`, `go.mod`)로 정하고, 정할 수 없으면 '일반'입니다.
`node_modules`와 빌드 결과물은 표시 파일이 있으면 **확인됨**, 없으면 **추정**으로 표시합니다.
먼저 맞은 폴더가 그 아래 전체를 차지하므로(`node_modules\pkg\dist`는 따로 나오지 않음) 항목 용량의 합에 중복이 없습니다.

## 파일 삭제 안전성

- 탐지는 이름·크기·속성만 읽고 파일을 열거나 수정하지 않습니다. 정리 과정에는 영구 삭제 코드 경로가 없습니다
  (영구 삭제는 [격리 폴더](#격리-폴더) 탭에서 사용자가 고르고 두 번 확인한 항목에만 합니다).
- 휴지통 이동은 `IFileOperation`(`FOF_ALLOWUNDO | FOFX_RECYCLEONDELETE`)으로 항목마다 실행합니다. 셸이 영구 삭제로 바꾸려 하면
  (휴지통 용량 초과 등) 진행 싱크에서 거부하고, 항목이 그대로면 다시 확인한 뒤 격리 폴더로 옮깁니다.
- 다음 중 하나라도 해당하면 그 항목은 건드리지 않습니다.

| 시점 | 거부 조건 |
|---|---|
| 경로 판정 | UNC·상대 경로, 260자 이상, 탐지 경로 밖이거나 탐지 경로 자체 |
| | Windows·`Program Files`·`ProgramData`, 볼륨 루트의 `$Recycle.Bin`·`System Volume Information` 등과 같거나 그 아래 |
| | 볼륨 루트, `Users`, 사용자·공용 프로필, 바탕 화면·문서·다운로드 등 알려진 폴더, `AppData`, 실행 중인 프로그램 폴더, 그리고 이들의 상위 |
| | 하위를 다 읽지 못한 항목(접근 거부·취소로 일부 누락) |
| | 격리 폴더(`.bytesieve-trash`)이거나 그 안 |
| 옮기기 직전 | 고정·이동식 드라이브가 아님(네트워크·CD 등), 이미 없음 |
| | 탐지 때와 종류가 다름, 링크로 바뀜, `GetFinalPathNameByHandleW`로 구한 실제 위치가 표시 경로와 다름(중간 폴더가 정션으로 바뀐 경우 등) |

## 격리 폴더

휴지통이 없는 드라이브(USB·외장 드라이브 등 이동식 드라이브)이거나 휴지통에 넣을 수 없는 항목은 영구 삭제하지 않고
**같은 드라이브의 격리 폴더**로 옮깁니다.

| 상황 | 처리 |
|---|---|
| 고정 디스크 | 휴지통으로 이동(기존과 같음) |
| 고정 디스크인데 셸이 영구 삭제하려 함(휴지통 용량 초과·휴지통 없는 볼륨) | 거부한 뒤 항목을 다시 확인하고 격리 폴더로 |
| 고정 디스크인데 셸이 항목을 건드리지 못하고 실패 | 다시 확인한 뒤 격리 폴더로 |
| 휴지통이 일부를 옮긴 뒤 실패 | 휴지통과 격리 폴더로 나뉘지 않게 실패로 남김 |
| 이동식 드라이브 | 처음부터 격리 폴더로 |

```
X:\.bytesieve-trash\                    격리 폴더(숨김, 드라이브마다 하나)
  20261031-153012-1\                    항목 폴더(격리한 시각 + 번호, 같은 이름도 겹치지 않음)
    entry.txt                           기록: 원래 경로, 볼륨 기준 상대 경로, 시각, 종류, 용량, 상태
    f\<원래 이름>                        격리된 파일·폴더
```

- **옮기기**: 같은 볼륨 안에서 이름만 바꿉니다(`MoveFileExW`, 복사·덮어쓰기 없음). 기록을 먼저 쓰고(`state=moving`) 옮긴 뒤 고칩니다
  (`state=moved`). 기록 파일은 임시 파일에 쓴 뒤 바꿔치기합니다. 옮기지 못하면 기록과 빈 폴더만 지우고 원래 항목은 그대로 둡니다.
- **제외**: 폴더 스캔과 정리 후보 탐지는 격리 폴더에 들어가지 않고, 정리 보호 판정은 격리 폴더 안의 항목을 거부합니다.
- **복원**: 원래 위치로 이름을 바꿔 돌려놓습니다. 같은 이름이 있으면 덮어쓰지 않고 건너뛰며, 처리 방법을 안내하고
  `이름 (복원됨).확장자`처럼 다른 이름으로 복원할지 묻습니다. 없어진 상위 폴더는 만듭니다. 드라이브 문자가 바뀌었어도
  기록의 상대 경로로 지금 드라이브 기준 위치에 복원합니다.
- **영구 삭제**: 대상 목록·용량과 복구할 수 없다는 안내를 보여 주고 두 번 확인받습니다. 항목 폴더가 격리 폴더 바로 아래이고
  격리 폴더가 링크가 아닌 실제 폴더인지(`GetFinalPathNameByHandleW`) 다시 확인한 뒤 지웁니다. 정션·심볼릭 링크는 따라가지 않고 링크만 지웁니다.
- **예외 처리**: 권한 부족·쓰기 금지, 다른 프로그램이 사용 중, 디스크 공간 부족(기록을 쓰지 못함), 같은 이름, 다른 볼륨, 격리 폴더가
  링크·파일로 바뀜을 구분해 항목별 결과로 보여 줍니다. 일부가 실패해도 나머지는 계속 처리합니다.

### 기록과 실제 상태가 어긋날 때

파일을 지우지 않고 상태로만 보여 주며 처리는 사용자가 정합니다.

| 상태 | 뜻 | 복원 | 영구 삭제 |
|---|---|---|---|
| 격리됨 | 기록과 파일이 모두 있음(기록이 `moving`이어도 파일이 옮겨져 있으면 정상) | 가능 | 파일과 기록 |
| 기록만 있음 | 격리된 파일이 없음 | 불가 | 기록과 빈 폴더만(다른 파일이 있으면 남김) |
| 기록 없음 | 기록이 없거나 손상됨, 상대 경로가 볼륨 밖을 가리킴, 사용자가 넣은 파일 | 불가(원래 위치 모름) | 그 항목 전체 |
